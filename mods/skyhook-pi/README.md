# Skyhook PI 0.1.9

Launcher-мод для автоматического производства всего набора P1 по типу планеты.
P2–P4 производятся обычным способом. Серверные файлы и архивы клиента не меняются:
мод подключает собственные обработчики и узкие преобразования кода в памяти.

## Совместимость

Node.js 24+, Native Launcher с loader/helper API 1 (минимум 1.0.69).
Исходники изучены по rrfarmer/main `cf368846f444`, package 0.12.9.
Версии 0.12.9/0.12.19 в manifest — фильтр Launcher, не подтверждение работы
произвольной Discord-сборки. Helper сверяет SHA-256 нормализованных исходников.
При `Unreviewed ...` мод не активируется. Не обходите guard.

В 0.1.1 добавлены четыре точных fingerprint из пользовательского отчёта
0.12.19: версии itemStore из `082916b3db47`, characterState/bootstrap из
`67053b412e09`, sovPlayerDeployment из `5267249207c0`. Их исходники найдены
в истории upstream, различия изучены; операции, используемые модом,
и места преобразования не изменены. Это поддержка этих конкретных файлов,
а не любых сборок с номером 0.12.19. Отказ 0.1.0 воспроизведён локально;
0.1.1 проходит проверку этого набора и продолжает отклонять неизвестные файлы.

Реальный Windows Launcher/EVE-клиент в ходе разработки здесь не запускались.
Первая установка предназначена для проверки на disposable-копии сервера/баз.
Перед установкой можно получить read-only отчёт из каталога EVE.js:

```powershell
node .\mods\skyhook-pi\inspect.cjs --root .
```

Фактическое имя каталога, выбранное Launcher, может отличаться; укажите путь
к `inspect.cjs` из распакованного ZIP. Отчёт содержит версии/хеши/отсутствующие
API-файлы, без токенов, конфигов и содержимого игровых БД. Для неподдерживаемой
сборки требуется отдельная сверка её исходников и адаптация мода.

В 0.1.2 исправлен `STORE_BUSY` при запуске дочерних wallet/scheduler процессов.
`fork()` наследует preload-моды; `isMainThread` не отличает дочерний процесс
от игрового сервера. Теперь мод подключается только для входного файла
`server/index.js`; дочерние процессы, helpers и worker threads не открывают
PI-склад и не устанавливают hooks. Проверка роли через переменную окружения
не подходит: дочерний процесс сначала наследует роль `world`.

При обновлении с 0.1.1 остановите сервер и дождитесь завершения его дочерних
процессов, затем замените ZIP через Launcher. Не удаляйте `state.sqlite` и
его служебные файлы: после завершения прежнего владельца склад открывается
штатно. Защита от запуска двух игровых серверов на одном складе сохранена.

В 0.1.3 исправлен пропуск основного сервера при `node .` / `node server`:
штатный `server/package.json` использует запуск через каталог. Путь из argv
теперь разрешается как модуль Node до сравнения с `server/index.js`.
Отклонённые отдельные процессы выводят `[SkyhookPI] skipped non-world process`
с PID и входным путём. Для основного процесса ожидается строка `0.1.3 loaded`,
затем `startup reconciliation complete`.

## Установка и работа

1. Остановите игровой сервер и клиенты. Для первой проверки используйте копию
   всей установки с отдельными gameStore и market и локальными адресами.
2. Launcher → Mods → Add ZIP → SkyhookPI-0.1.9.zip → включить.
3. Запустите сервер и клиент. Ожидается `[SkyhookPI] 0.1.7 loaded`.
4. Установите настоящий Orbital Skyhook (`81080`) у нужной планеты. Используется
   штатный запуск из грузового отсека; предмет структуры расходуется штатно.
   В изученном сервере этот путь не требует суверенитета. Поддерживаемая область:
   highsec, lowsec, nullsec, WH; Abyssal запрещён штатной проверкой.
5. Нужна **корпорация игроков**: ресурсы принадлежат корпорации. NPC-корпорация
   не получает общий доступ к такому складу. Дождитесь активации структуры.
6. Введите `!skyhookpi` (или `/skyhookpi`), нажмите «Обновить», выберите скайхук
   слева и нажмите «Включить». На одну планету разрешена одна привязка PI-производства.
7. Все P1 этой планеты начисляются одновременно: по 20 единиц за 5 минут,
   240/час каждого товара. Лимит каждого — 40 320 единиц (7 суток).
8. Подлетите к скайхуку и выберите P1 справа, количество и трюм. «Забрать / повторить»
   выдаёт столько, сколько помещается. Планетарный и инфраструктурный трюмы
   проверяются по реальным ограничениям вашего корабля; неподходящий запрещён.

Управление: установивший структуру персонаж, остающийся в corp-владельце,
CEO или director. Для скайхуков, установленных до мода, управление доступно
руководству корпорации. Забрать груз может любой текущий член corp-владельца.

Закрытие клиента не останавливает добычу. После штатного перезапуска учитывается
прошедшее время до лимита склада. При «Паузе» время не накапливается.
Заполненное отделение не мешает остальным товарам и не хранит скрытый избыток.

После неоднозначного ответа клиент сохраняет тот же requestID для повтора.
Повторяется исходная операция, даже если выбран другой товар. Достоверный ответ
снимает pending; затем можно выполнить следующую операцию. Перезапуск клиента
не дублирует уже выданный груз: сервер восстанавливает незавершённые выдачи
по сохранённым квитанциям.

## Настройки и данные

Необязательный `config/skyhook-pi.config.json` в корне установки:

```json
{
  "amountPerCycle": 20,
  "cycleMs": 300000,
  "capacityPerProduct": 40320
}
```

Все значения — положительные целые; цикл не меньше секунды, количество/лимит
не больше миллиарда. Изменение требует перезапуска. Сначала начисляется старый
период по сохранённым настройкам, затем применяются новые. Уменьшение ёмкости
не удаляет накопленный груз; новые начисления ждут освобождения места.

Состояние находится в `_local/mods/skyhook-pi/state.sqlite`, вне каталога пакета.
Не открывать его на запись сторонними программами и не запускать второй сервер
на той же установке. Перед резервным копированием остановить сервер;
копировать согласованно gameStore и весь `_local/mods/skyhook-pi`.

## Структура, таможня и отключение мода

Штатные реагенты скайхука и обычные PI-колонии не используются как склад мода.
Runtime-адаптер сохраняет синтетическую POCO рядом со скайхуком, не воскрешая
уничтоженные таможни и не удаляя существующие.

Перед снятием структуры поставьте производство на паузу и заберите весь груз.
Снятие с остатками/незавершённой выдачей запрещено. Уничтожение структуры
прекращает производство и уничтожает невыданный запас; уже выданный груз
не отбирается. При передаче владельца склад передаётся новой корпорации,
производство ставится на паузу; незавершённая выдача блокирует передачу.

Отключение/удаление: остановите сервер и клиенты, используйте действие Launcher.
Helper фиксирует паузу, внешний SQLite-склад сохраняется. После включения
производство нужно запустить явно. Ручное удаление каталога в обход helper
не является поддерживаемым способом отключения и не фиксирует паузу.

После отключения runtime-адаптера сервер возвращается к штатным правилам POCO:
стоящий скайхук может скрывать синтетическую таможню. Чтобы полностью вернуться
к обычной PI-механике, сначала освободите склад и штатно снимите скайхук.

## Приёмка на Windows

На disposable-копии проверить:

- Установка через Launcher, окно и совместная работа с AutoMining/Market Search.
- Настоящий launch у планеты, Start; через два цикла +40 каждого допустимого P1.
- Restart/offline catch-up, Pause/Resume, уменьшение лимита без потери груза.
- Сбор рядом/издалека, обычный и специальный трюм, недостаток места, повтор клика.
- Другой персонаж в corp и чужая corp; управление installer/CEO/director.
- POCO остаётся видимой; обычный импорт/экспорт колонии работает до и после
  установки скайхука. Уничтоженная POCO не появляется снова.
- Снятие с запасами отклоняется; после паузы и сбора разрешается; уничтожение
  обнуляет PI-склад; смена corp не сохраняет доступ старого владельца.
- Disable/remove/reinstall сохраняют склад и не начисляют время отключения.

Здесь выполнены проверки на временных SQLite и адаптерах, включая обработку
изменённого реального upstream-исходника POCO. Это не заменяет native gameplay.
Новый автоматический test suite в репозиторий не добавлен по AGENTS.md.

## Большой пакет входа и совместная работа модов

Исправлена ошибка `UI delivery skipped: Combined login payload is too large`.
Если составное выражение превышает 256 KiB, сжимается всё выражение целиком,
с сохранением прежнего результата и порядка исполнения. Лимит передаваемого
выражения остаётся 256 KiB; исходный текст ограничен 2 MiB. Если сжатие не
помогает, лог сообщает исходный и итоговый размер, вход в игру сохраняется.

Для совместного использования обновить **оба** пакета: Skyhook PI 0.1.4 и
Market Search 0.1.1. Иначе старый Market Search может пропустить своё окно
до выполнения исправленного обработчика Skyhook PI. После обновления
перезапустить сервер и полностью закрыть/запустить клиент. Успешное сжатие
отмечается `UI delivery packed: source=... bytes, wire=... bytes`.

Локально проверены оба порядка доставки, сохранение результата и побочных
эффектов Python-выражения, ограничения размера и композиция с исходниками
AutoMining 1.2.14 (`48f00a6`). Полная Windows/Python 2.7 приёмка не выполнена.

## Управление несколькими скайхуками (0.1.5)

Слева — одна строка на структуру: система, планета/ID, состояние и склад.
Процент — сумма запасов относительно суммарной ёмкости; в скобках число
заполненных отделений / число продуктов. Справа — P1 выбранного скайхука.
Стрелка отмечает текущий выбор; при обновлении выбор сохраняется, пока
структура/продукт остаётся доступным. Если фильтр скрывает структуру,
выбирается первая видимая; правый список всегда относится к выбору слева.

Фильтры: все системы / текущая / конкретная; все состояния / работают /
пауза / не настроены / есть заполненные отделения. Последний означает хотя
бы один продукт на лимите. Включение и пауза действуют на выбранную структуру
целиком и доступны удалённо при наличии прав — продукт выбирать не требуется.

Доступность кнопки сбора обновляется раз в секунду по клиентской дистанции.
В другой системе, на станции или далеко от структуры кнопка недоступна,
рядом нужно выбрать продукт с запасом. Точную дистанцию, права и вместимость
в момент выдачи повторно проверяет сервер. Остатки обновляются кнопкой
«Обновить»; после цикла добычи или сбора обновите список.

При неподтверждённой операции кнопка меняется на «Повторить запрос»,
показывается ID исходного скайхука. Повтор доступен даже после изменения
фильтра/выбора/дистанции и отправляет прежний requestID и параметры.

0.1.4 пользователь подтвердил как рабочую после установки структуры и
открытия окна; отдельный протокол полной игровой приёмки не получен. Для 0.1.5 проведены локальные UI-проверки на
100 структурах; новый layout и клиентскую дистанцию нужно проверить в Windows.
Market Search повторно обновлять не требуется: версия 0.1.1 совместима.

## Открытие из неокома

Требуется Launcher 1.0.69+ с client-menu API v1. После обновления ZIP и
перезапуска сервера/клиента откройте **Neocom → Mods → Skyhook PI**
(русское название пункта: **Skyhook PI**). Пункт также доступен в общем меню
**Insider → MODS**, если оно предоставляется Launcher.

Адаптер `client/menu.py` регистрирует только пункт и вызывает существующее
окно. Пункт доступен после готовности companion текущего персонажа;
до этого проверьте сообщения доставки/готовности. Команда в чате сохранена.
Сам неоком, его иконку и общий список рисует Launcher. При выгрузке удаляется
только собственная регистрация; остальные моды не затрагиваются.

Локально проверены контракт регистрации, готовность, смена owner, повторная
регистрация и очистка на API-адаптере. Отображение в Windows не проверено.

## Обновления из Launcher

Источник: публичные релизы https://github.com/klimesrenz/evejs-mods/releases .
Первую версию с блоком updates установить вручную через Add ZIP. Далее
использовать Check mod updates и кнопку Update после просмотра изменений.
Проверка не устанавливает обновление автоматически. Перед обновлением
остановить сервер и закрыть клиент. Совместимость исходников проверяется
helper мода; ограничения версии сервера сохраняются.

Идентификатор мода и пути данных сохранены. Склад Skyhook PI и конфиги
вне каталога пакета не входят в ZIP и не требуют preserveFiles. После
обновления проверить состояние производства, при необходимости включить
его снова. Подробный порядок релизов — в README репозитория.

## Проверка обновления через Launcher

В 0.1.8 номер версии отображается в заголовке окна: **Skyhook PI 0.1.8**.
После обновления через Check mod updates → Update и перезапуска сервера/клиента
откройте окно из Mods и сверяйте этот номер. Это подтверждает получение
нового клиентского кода, а не только замену записи в списке Launcher.

Перед обновлением закройте клиент и остановите сервер. Для Skyhook PI
запишите остатки до обновления; после сверяйте их с учётом прошедших циклов,
выбранной паузы и ёмкости. Если helper поставил производство на паузу,
включите его снова. Параметры производства и формат склада в этом выпуске
не изменены. Для Market Search проверьте поиск известного товара.

В 0.1.9 исправлен выбор строк: клик по скайхуку или материалу больше не
перезагружает соответствующий список и не меняет его порядок/прокрутку.
Штатное выделение заменяет маркер в названии; после Refresh выбор сохраняется.
