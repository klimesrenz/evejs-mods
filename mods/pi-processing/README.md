# Переработка PI 0.1.7

Отдельное окно Mods для производства P2–P4 из материалов личного ангара.
Можно использовать P1 со Skyhook PI или купленные материалы. Чертежи,
планетарные фабрики, ISK, навыки и промышленный сервисный модуль не требуются.

## Производство

1. Докнитесь на NPC-станции или в доступной цитадели. Положите материалы
   непосредственно в личный ангар, вне кораблей и контейнеров.
2. Mods → Переработка PI, либо чат `!piprocessing`.
3. Выберите конечный продукт и число партий, нажмите «Рассчитать» или «Максимум».
4. «Запустить» списывает всю партию сырья. Отмены задания нет.
5. Во вкладке «Задания» после таймера нажмите «Забрать» в том же месте.

Все рецепты P2–P4 раскрываются до P1 по серверным схемам. Промежуточные
P2/P3 в ангаре не требуются и не расходуются: списывается P1, выдаётся
только выбранный конечный продукт. Общие компоненты суммируются.

Время равно самому длинному пути производства: независимые промежуточные
ветви идут параллельно, следующий этап ждёт их готовности. В проверенном
CCP SDE 3396210 это 1 час для P2, 2 часа для P3 и 3 часа для P4.
Число партий не увеличивает время — они исполняются параллельно.
Минимальная партия рассчитывается так, чтобы все промежуточные циклы были
целыми; округления и остатки промежуточных продуктов не создаются.

Пример: 80 Oxygen + 80 Biomass + 80 Silicon + 80 Industrial Fibers
дают 3 Data Chips за 2 часа. «Максимум» учитывает только нужные P1 в ангаре.
Точный состав и выход показываются в окне; они зависят от установленного SDE.
Игрового лимита линий/заданий нет. Технически одна партия ограничена
2147483647 единицами каждого входа/выхода и 10000 исходными стопками;
объедините стопки или разделите чрезмерно большую партию на задания.
Промежуточные тиры отдельно запускать не нужно. Автоповтора и частичной выдачи нет.

Таймер продолжает идти при закрытом клиенте, остановленном сервере и
отключённом моде. Готовые партии сохраняются без срока истечения.
Результат всегда привязан к исходному ангару. При потере доступа к структуре
нужно восстановить доступ; при её уничтожении/снятии результат остаётся в БД,
но получить его в другом месте нельзя. Автоматического Asset Safety нет.

Если ответ потерян, используйте «Повторить запрос»: сохранённый идентификатор
не позволит повторно списать сырьё/выдать результат. При смене места сначала
вернитесь в место исходного запроса. Не удаляйте pending-запрос вручную при
ошибке хранилища: сначала восстановите сервер и повторите запрос.

## Установка и проверка на Windows

Требуется Native EVE.js compatibility identity 261108.1, Node.js 24+, Launcher 1.0.74+.
Helper дополнительно проверяет конкретные исходники. Неизвестный build
отклоняется; принимаются только fingerprints fork build 261109.1, commit
`e7b2f092eff3cf6ecd7838ee899b08c438707eff`. Guard не отключать.
Файл `lib/reviewed.json` содержит нормализованные SHA-256 изученных файлов.

1. Остановить игровой сервер, закрыть EVE-клиенты.
2. Launcher → Mods → Add ZIP → `PIProcessing-0.1.7.zip` → Enable.
3. Запустить сервер и клиент; открыть окно из общего меню Mods.
4. На первой проверке запустить 1 партию доступного P2-рецепта. Сверить списание
   всех материалов. Перезапустить сервер до завершения, дождаться таймера,
   получить результат и сверить количество в ангаре.
5. Повторить в цитадели, проверить отказ получения на другой станции,
   смену персонажа и работу рядом с Skyhook PI/Market Search/AutoMining.

При `Unreviewed ...` нужны указанный файл и версия работающей сборки для
адаптации. `UI not ready` — проверить серверный лог, перезапустить клиент.
`STORE_BUSY` — другая копия сервера владеет БД; живой процесс не вытеснять.
Ошибки recovery требуют сохранения БД и логов для диагностики, а не удаления.

## Данные и обновления

Задания: `<EVE root>/_local/mods/pi-processing/state.sqlite` с WAL/SHM рядом.
Они не входят в ZIP и сохраняются при обновлении/удалении пакета. Перед
окончательным удалением мода заберите готовые партии. Для резервной копии
остановите сервер и копируйте каталог состояния целиком; не откатывайте
отдельно БД мода без согласованного состояния host inventory и его квитанций.

Пакет использует источник будущих обновлений `klimesrenz/evejs-mods`,
теги `pi-processing-v...`; первое подключение через Add ZIP. Доступность
обновления зависит от публикации соответствующего GitHub Release.

## Статус проверки

Локально проверены расчёты, SQLite rollback/reopen/lease, реальные функции
атомарного списания и квитанций на двух изученных исходниках, recovery заданий,
RPC, сохранение pending-запроса, helper и композиция доставки/преобразований.
Для host-функций использован временный адаптер хранения: это не запуск полного
Windows-сервера. Каталог реального Windows SDE и исполнение окна в клиентском
Python 2.7 требуют проверки пользователем. Синтаксическая проверка их не заменяет.

## Обновление с 0.1.0

После публикации 0.1.1: остановить сервер и закрыть клиенты → Check mod updates
→ Update → restart. Уже запущенные задания сохраняют прежние входы, выходы
и срок завершения. Новые задания используют P1. Неотправленный старый запрос
Start потребует нового расчёта; подтверждённый повтор вернёт прежнее задание.

Локально проверены все 53 цепочки официального SDE 3396210, целочисленный
баланс промежуточных продуктов, время ветвей, лимит по P1 и переход старых
заданий. Работа 0.1.0 в игре подтверждена пользователем; новый экран и
производство из P1 версии 0.1.1 требуют отдельной Windows-приёмки.

## Список заданий в 0.1.2

После получения продукции задание исчезает из списка. Уже полученные ранее
партии также скрываются. Готовые, но ещё не забранные партии остаются видимыми.
Записи заданий и запросов сохраняются в базе для защиты от повторной выдачи;
обновление не требует очистки БД. После получения выбранного задания его
детали очищаются.

## Поддержка EveJS 261018.1: 0.1.4

Пакет проверен по host-контрактам EveJS Core `dbcd89a79`. Идентификатор
персонажа берётся через штатный session identity. Recovery теперь отличает
достоверно отсутствующую inventory-квитанцию от неопределённого чтения: задания
без commit больше не остаются навсегда в `starting` или `delivering`.

Совместимость со старыми ветками 0.12.x этим пакетом не заявляется. Формат базы
заданий и рецепты не изменились.

## Поддержка EveJS 261028.1 / fork build 261029.1: 0.1.5

Пакет проверен по host-контрактам текущего EveJS Core fork build `261029.1`,
основанного на commit `3df5c95ded835605a837229ad4e3eb730929ca58`, при
compatibility identity root/server `261028.1`. Повторно изучены семь изменившихся
guarded-файлов: атомарное списание и durable receipt в item store, inventory
notification, расширение PlanetMgr RPC, доступ к структуре, marshal packet hook и
оба chat entrypoint. Их используемые модом сигнатуры и границы сохранились;
изменения Core усиливают authority и добавляют независимые runtime-функции.
Transform item store применяется к LF и CRLF одинаково и компилируется на точном
fork build 261029.1. Формат базы заданий и рецепты не изменились.

## Поддержка EveJS 261108.1 / fork build 261109.1: 0.1.7

Пакет ограничен Core `261108.1`, fork build `261109.1`, commit
`e7b2f092eff3cf6ecd7838ee899b08c438707eff`; guarded hashes находятся в
`lib/reviewed.json`, происхождение — в `PROVENANCE.md`.

Списание входов переведено с compiler transform `itemStore` на штатный Core
`exchangeInventoryItemStacksIdempotent(requests, [], options)`. Пустой список
выходов важен: Core атомарно списывает P1 и durable receipt, но готовый продукт
по-прежнему не выдаётся до завершения сохранённого таймера. Отдельная выдача и
receipt recovery сохранены. Loader больше не устанавливает itemStore compile hook.

Source-only tests покрывают duplicate receipt, конфликт fingerprint и
authoritative absence, а также LF/CRLF guards. Формат SQLite, рецепты и уже
запущенные delayed jobs не изменены.
